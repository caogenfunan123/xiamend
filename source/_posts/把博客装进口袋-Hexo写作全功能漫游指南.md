# 把博客装进口袋：Hexo 写作全功能漫游指南

我想象过这样一种写作：清晨的地铁里，灵感像车窗外的光一闪而过，我掏出手机，轻点几下，一篇文章的雏形已经安静躺在本地草稿箱；走到公司楼下，AI 已经帮我把冗长的句子修剪得干净利落；午休时顺手一点，文章推送到了 GitHub，几分钟后，世界便能读到它。

这不是科幻，而是「Hexo 写作」正在做的事。

---

## 第一幕 创作中枢：让书写回归纯粹

### 指尖上的 Markdown 书房

编辑器是写作的第一现场。它不复杂，却足够周全——标题、粗体、引文、代码块、列表的快捷插入都摆在触手可及处，让你专注于文字本身。文章类型可自由切换为 Post 或 Page，每一个框架的 FrontMatter 都被悄悄翻译成正确的方言。

你会喜欢它的**自动保存**：当你停下来喝水、发呆、刷手机，它在两秒后默默保存。它不催促，只是安静地守护每一份灵感，绝不让你因意外退出而捶胸顿足。

### 一键发布，与世界连接

写完后，发布不再是玄学。点一下「发布」，工具会循着框架的规则，把文件放到正确的目录，生成正确的文件头。若有图片想嵌入文章，它会代为上传到 GitHub 图床，还顺手压缩一下尺寸。标签、分类、封面，这些琐碎的体力活都交给了它。

更妙的是，它天然懂得 9 种主流静态博客框架——Hexo、Hugo、Jekyll、VuePress、Gatsby、Next.js、Astro、Pelican、11ty。你只需在添加仓库时告诉它一次，之后的每一步操作都会自动切换成那座城堡的语言。

---

## 第二幕 AI 智囊团：五位隐形写作助理

如果说编辑器是双手，那么 AI 就是这双手背后的思考。

应用内部住着五位各司其职的助理：

- **博文创作**：从零到一、润色改稿、扩写精简、SEO 优化——你只需要说人话。
- **页面创作**：关于、友链、归档、404，一键生成符合框架规范的独立页面。
- **主题开发**：新建主题、修改源码、快照备份、一键回滚，把改主题的恐惧化为春风。
- **主题迁移**：从 Hugo 迁到 Hexo？从 Jekyll 搬到 Astro？它会全程陪同，跨过格式的鸿沟。
- **站点巡检**：检查代码质量、验证配置正确性、预判构建风险，像一位贴心的站医。

每一个会话都有呼吸感：回复逐字浮现，思考时有圆点轻轻跳动，不耐烦了可以随时叫停。你们的对话会被妥帖保存，哪怕杀掉后台，再次打开，它依然记得你们谈过什么。

### 模型之下，是聪明的调度

你以为 AI 只是聊天？并不。你可以在设置中添加多枚模型，分门别类——代码、对话、长文本。工具会默默记录它们的响应速度和成功率，并在某个模型超时或失败时，自动唤起替补。上下文不会断，你甚至感觉不到发生了切换。

### 自发检查，把粗心拦在门外

生成完代码，它不会直接交差。先跑 6 项本地检查——HTML 标签是否闭合、CSS 路径是否有效、YAML 缩进是否合法、代码块是否完整、模板标签是否配对、文件引用是否健全。若发现可疑，再调 AI 做一次深度体检。你拿到的，往往已是经过考场的答卷。

## 第三幕 治理与迁移：不止是写作

### 一台掌上的 Git 实验室

Git 从来不是电脑的专利。多仓库、多 Token、文件 CRUD、提交历史、差异对比——这些功能被装进小小的 App 里，像一位随身携带的版本管理员。当你对主题改动犹豫不决时，一个快照备份，就能让时光倒流。

### 跨框架迁徙的温柔向导

从 GitHub 克隆一个主题，AI 识别它的血缘，然后一行一行地把模板语法翻译成目标框架的方言。迁移完成后，还能逐文件查看差异，勾选想并入的文件，最后才推入 `themes/`。整个过程被拆成 6 步，每一步都有台阶可踩，不用一步跨过悬崖。

### 其他让人安心的细节

批量上传旧文章、RSS 订阅、模板与片段素材库、直接编辑 `_config.yml`、内嵌 WebView 预览站点、WebDAV 云端同步……这些散落的工具，被一一收拢在侧边栏里，随取随用。

---

## 第四幕 后花园：设置与自愈

设置中心像一座精心打理的花园：主题色可随心更换，GitHub Token 与仓库可以多份并存，AI 配置、图床、Cloudflare 钩子、自动保存开关，全部一目了然。

最让人放心的是「退出保护」。当你手中还有未保存的修改，它会轻轻拉住你，给你四个选择——保存并发布、仅本地保存、放弃修改、或者，再想想。

至于发布之后的闭环，GitHub Actions 会自动接管：推代码、构建 APK、上传 Artifacts、甚至创建 Release。一切都是自动化，你要做的只是轻轻一点。

也许有一天，你会发现——博客已经不只属于书房的电脑，而是随身携带的一种生活方式。
